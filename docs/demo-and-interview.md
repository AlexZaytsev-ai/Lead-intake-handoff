# Демонстрация и объяснение проекта

## Запись на 2–3 минуты

Использовать отдельного бота и чистый тестовый чат. Заранее открыть группу менеджеров и последнюю execution. Секреты и настройки credentials в запись не включать.

1. Коротко обозначить задачу: собрать заявку из свободного текста, ответить на вопросы и передать менеджерам структурированную сводку.
2. Написать: «Нужен косметический ремонт квартиры. Вы работаете по договору?» Показать ответ про договор и следующий вопрос анкеты.
3. Ответить: «48 м². Можно оплатить ремонт ипотекой?» Показать отсутствие выдуманного обещания и продолжение сбора.
4. Написать оставшиеся данные и вопрос о гарантии из `testing.md`. Показать ответ и завершение передачи.
5. Переключиться в группу: показать сводку с именем, контактом, параметрами ремонта и причиной передачи.
6. Написать дополнение и показать его в группе.
7. Показать успешную execution и итоговые статусы в БД. Завершить ограничениями: общий чат без назначения менеджера, поиск по словам, спорные доставки проверяются вручную.

Отказ от имени и раннюю просьбу сотрудника можно показать отдельными короткими фрагментами на новых тестовых заявках. Не пытаться сбросить переданную заявку командой /start: она не создаёт новую.

## План рассказа на пять слайдов

Это текстовый план для последующей презентации, не готовый слайд-дек.

1. **Задача.** Менеджер получает разрозненные сообщения. Бот собирает сведения и передаёт сводку. Реальные показатели экономии времени не измерялись.
2. **Путь заявки.** Telegram → сохранение → извлечение AI → вопросы/RAG → сводка → группа → подтверждение.
3. **Данные и решения.** leads хранит состояние, messages — входящие тексты и обработку, handoffs — отправку сводки и подтверждение. Решение о следующем шаге принимает JavaScript по явным правилам.
4. **Надёжность.** Уникальные ограничения, сохранение до AI, ID отправок, SQL retries, предупреждения и проверенное восстановление одного вида статуса. Отдельно назвать риск дублей.
5. **Результат и развитие.** Полный тест пройден; дальнейшие задачи: новые заявки того же клиента, ответственный менеджер, более качественный поиск, доставка и конкурентная обработка.

## Вопросы на собеседовании

**Что здесь делает AI, а что обычный код?**

AI извлекает данные, выделяет тему поиска и формулирует ответ по фрагментам. SQL сохраняет состояние. JavaScript выбирает следующий вопрос или передачу. Отправкой управляет workflow.

**Зачем Structured Output Parser?**

Он задаёт ожидаемую структуру ответа и типы полей. Это помогает передавать результат в SQL. Валидный JSON не гарантирует, что модель правильно поняла сообщение; ограничения БД и сценарные тесты всё равно нужны.

**Почему данные сохраняются до модели?**

Чтобы входящий текст не исчез при ошибке AI. По записи можно увидеть, какое сообщение не обработалось. Автоматический replay при этом ещё не реализован.

**Что здесь называется RAG?**

Перед генерацией ответа получаем подходящие фрагменты из внешней таблицы знаний и передаём их модели. Retrieval лексический, через PostgreSQL, без векторов. AI помогает преобразовать вопрос в поисковую тему.

**Как бот ведёт диалог без chat memory у модели?**

Собранные значения и последнее заданное поле хранятся в leads. В parser передаются текущее сообщение и название последнего вопроса. Для составных неоднозначных ответов этого контекста может не хватать.

**Откуда защита от дублей?**

Уникальность входящего сообщения в рамках заявки и уникальность передачи в чат менеджеров. Эти ограничения не гарантируют единственную доставку Telegram и не решают все гонки параллельных сообщений.

**Почему sent и handed_off хранятся отдельно?**

Первое описывает запись передачи, второе — состояние заявки. Последовательные SQL-записи могут рассогласоваться при сбое; мониторинг умеет исправлять проверенный случай.

**Как организована работа двух менеджеров?**

Они могут видеть заявки в общей группе. Назначение ответственного и автоматическая маршрутизация между менеджерами пока отсутствуют. Ответ из группы клиенту бот не передаёт.

**Что ты сделал с помощью AI?**

Проект разрабатывался с помощью AI. Я собирал и настраивал workflow, проводил сценарные проверки, сверял отправки и состояния базы, разбирал найденные ошибки. Важно уметь проследить конкретную заявку через сохранение, выбор следующего шага и передачу, а не утверждать, что весь код написан самостоятельно.

**Готово ли это для реального бизнеса?**

Это демонстрационный проект с проверенным основным путём. Перед эксплуатацией нужны согласованные условия компании, правила хранения данных, обработка вложений, конкурентных сообщений, повторных заявок и доставки после сбоев.
