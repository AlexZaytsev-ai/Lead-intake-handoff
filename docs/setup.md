# Запуск демо

Нужны работающий n8n с доступным Telegram webhook, PostgreSQL, отдельный тестовый Telegram-бот и доступ к выбранной AI-модели. Проект не содержит готового Docker Compose, секретов и резервной копии рабочей БД.

## База

1. Создать отдельную пустую БД и роль с правами создавать таблицы в `public`.
2. Выполнить `sql/001_schema.sql`, затем `sql/002_demo_knowledge.sql` через SQL-клиент либо отдельную PostgreSQL-ноду.
3. Не выполнять схему поверх рабочей БД: файл не является миграцией. Имена таблиц и ограничения сверены с выгрузкой структуры, но identity выбран как `GENERATED BY DEFAULT` для запуска с нуля. Исходный запрос не содержал режима identity, точности типов numeric и дополнительных индексов; это не побайтовый pg_dump.
4. Оба workflow подключить к одной БД. Внешние ключи не удаляют историю каскадно.

## Импорт workflow

1. Импортировать оба JSON из `workflows/`. Они отключены, credentials нужно назначить заново.
2. Во всех PostgreSQL-нодах выбрать один PostgreSQL credential.
3. В Telegram Trigger и всех Telegram-нодах выбрать credential своего тестового бота.
4. В двух OpenAI Chat Model назначить credential, проверить модель и доступ к ней. Подключения моделей к цепочкам уже сохранены в JSON.
5. Использовать отдельного бота для этого демо: другой Telegram Trigger с тем же ботом может изменить его webhook.

## Адреса чатов

| Workflow / нода | Что заменить |
| --- | --- |
| Основной / «Подготовить передачу» | Второй элемент Query Parameters: `REPLACE_MANAGER_CHAT_ID` заменить числовым ID группы, сохранив строковые кавычки |
| Основной / «Передать сообщение менеджеру» | Chat ID `REPLACE_MANAGER_CHAT_ID` заменить тем же ID группы |
| Мониторинг / «Сообщить о зависшем сообщении» | Chat ID `REPLACE_ALERT_CHAT_ID` заменить ID личного/служебного чата для предупреждений |
| Мониторинг / «Сообщить о зависшей передаче» | Chat ID `REPLACE_ALERT_CHAT_ID` заменить тем же ID предупреждений |

Заполнители намеренно не являются рабочими числовыми ID. С ними отправка и преобразование в bigint не пройдут. Использовать настоящее числовое значение, для группы обычно отрицательное. Бот должен быть добавлен в группу с правом отправки. Для личных предупреждений получатель сначала должен открыть диалог с ботом.

ID клиента определяется из входящего события, вручную его подставлять не нужно.

## Проверка перед включением

- В Structured Output Parser проверить `knowledge_query` в `properties` и `required`.
- В «Найти знания RAG» параметр берётся из `Basic LLM Chain.output.knowledge_query`, тестового слова «ипотека» там нет.
- В «Ответить по базе знаний» вопрос берётся из сообщения клиента, фиксированного тестового вопроса нет.
- В трёх SQL-нодах «Отметить передачу», «Обновить статус заявки», «Подтвержден» включены 3 попытки с интервалом 1000 мс. У Telegram-нод слепой повтор не включён.
- В Schedule Trigger мониторинга явно выставить желаемый интервал, например 1 минуту, и timezone. В исходном экспорте указан тип интервала `minutes` без явного числа. Возраст записи для предупреждения — больше 5 минут, повторное предупреждение — не чаще раза в час на запись.
- Проверить адрес предупреждений. В уведомление попадает текст клиента: это служебный чат, доступ к нему должен быть ограничен.
- Сохранить/опубликовать и включить workflow средствами своей версии n8n. Зелёный ручной запуск не доказывает, что workflow активен по расписанию.
- Пройти сценарий в `testing.md` на новом тестовом Telegram-чате и проверить статусы в БД.

Проверенные ответы о гарантии, бесплатном замере и сроке связи относятся исключительно к вымышленным условиям. Для реального бизнеса сначала согласовать их с компанией.
